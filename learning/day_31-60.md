# Senior Python Engineer RPG — Enterprise ERP + AI Roadmap

## Phase 2: Days 31–60 — Domain Expansion, Clean Architecture, Async Operations, Reporting, and RAG v1

**Working rhythm:** Monday–Saturday are working days. Sunday is always rest and is not counted as a roadmap day.  
**Daily time budget:** 3–4 hours.  
**Main project:** Enterprise ERP System.  
**Phase objective:** Transform the Phase 1 ERP foundation into a stronger business platform with real domain modules, cleaner service boundaries, deeper authorization, async workflows, reporting, search, and the first useful RAG assistant.

---

## Phase 2 Theme

You start Phase 2 as a **Level 2 Strong Junior / early Level 3 Middle candidate** and finish as a **solid Level 3 Middle Engineer** with early **Level 4 Strong Middle architecture habits**.

The main engineering shift in this phase:

- From simple CRUD to business workflows.
- From route handlers/schemas doing too much to explicit application services.
- From static records to state machines, audit trails, approvals, and async side effects.
- From AI demo endpoint to ERP-aware RAG v1.
- From basic tests to business-critical test coverage.

---

## Phase 2 Assumptions

Phase 2 depends on the Phase 1 foundation:

- FastAPI backend exists, with Flask and Django/DRF kept as secondary comparison tracks.
- PostgreSQL is connected.
- Custom user model exists.
- JWT authentication works.
- Organization, branch, department, employee models exist.
- RBAC foundation exists.
- Audit log foundation exists.
- CRM and inventory foundations exist.
- Redis and Celery are connected.
- Document management and semantic search prototypes exist.
- Basic AI assistant API boundary exists.
- CI runs tests.

If any Phase 1 item is incomplete, complete it before starting Day 31.
