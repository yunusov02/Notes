# Senior Python Engineer RPG — Enterprise ERP + AI Roadmap

## Phase 1: Days 1–30 — Core Foundation, Auth, RBAC, ERP Skeleton, AI-Ready Base

**Working rhythm:** Monday–Saturday are working days. Sunday is always rest and is not counted as a roadmap day.  
**Daily time budget:** 3–4 hours.  
**Main project:** Enterprise ERP System.  
**Phase objective:** Build a clean, tested, extensible ERP monolith foundation that can later evolve into event-driven, AI-powered, distributed architecture.

---

## Phase 1 Theme

You start as a **Level 1 Junior Builder** and finish the phase as a **Level 2 Strong Junior / early Level 3 Middle candidate** with a real ERP foundation.

This phase avoids isolated tutorials. Every concept must be applied directly to the ERP.

### Primary Outcomes

By the end of Day 30, the ERP must include:

- FastAPI backend foundation with Flask and Django/DRF as secondary tracks
- PostgreSQL database
- Custom user model
- Authentication with JWT
- Organization, branch, department, employee models
- RBAC foundation
- User management APIs
- Audit log foundation
- CRM foundation
- Inventory foundation
- Basic document management
- Redis and Celery foundation
- Basic notification center
- Basic semantic search prototype
- Basic AI assistant endpoint
- Initial analytics/reporting dashboard APIs
- Automated tests
- GitHub Actions CI
- Architecture documentation
- Day 30 boss battle release

# Phase 1 Architecture Rules

These rules must be followed during Days 1–30:

1. **Do not put business logic in route handlers.** Use services for workflows.
2. **Do not let schemas perform complex business decisions.** They validate input and shape output.
3. **Every important action must be testable.** Prefer service tests plus API tests.
4. **Every organization-scoped model must enforce organization filtering.** No cross-tenant leaks.
5. **Every future AI feature must respect RBAC.** AI is not a backdoor.
6. **No real LLM integration before the retrieval boundary is safe.** Phase 1 uses deterministic/mocked AI responses.
7. **Documentation is part of the deliverable.** If architecture is not written, it is not finished.
8. **Saturday is for review, refactoring, docs, and architecture inspection.** Do not skip this.
