# Senior Python Engineer RPG — Enterprise ERP + AI Roadmap

## Phase 3: Days 61–90 — Event-Driven ERP, Real-Time Systems, Advanced Search, Analytics, and Architecture Migration

**Working rhythm:** Monday–Saturday are working days. Sunday is always rest and is not counted as a roadmap day.  
**Daily time budget:** 3–4 hours.  
**Main project:** Enterprise ERP System.  
**Phase objective:** Move the ERP from a modular monolith with useful business workflows into a more senior-grade platform with domain events, CQRS-style reads, real-time notifications, stronger analytics, advanced search, and a first major architecture migration.

---

## Phase 3 Theme

Phase 3 is where the project starts looking less like a CRUD portfolio app and more like an enterprise platform.

You are no longer only creating tables, schemas, route handlers, and forms. You are now building:

- Event-driven workflows
- Reliable async processing
- Read models for reporting
- Audit-grade business history
- Search infrastructure
- Real-time collaboration features
- AI copilot improvements
- Analytics pipelines
- Architecture decision records
- Migration plans that preserve working software

You start Phase 3 as a **solid Level 3 Middle Engineer** and finish as a **Level 4 Strong Middle Engineer** approaching **Level 5 Senior thinking**.

---

## Phase 3 Assumptions

Phase 3 depends on Phase 1 and Phase 2:

- FastAPI backend is stable, with Flask and Django/DRF maintained as secondary tracks.
- PostgreSQL schema includes core ERP modules.
- JWT authentication and RBAC are implemented.
- HRM, Payroll, Inventory, Warehouse, Procurement, Sales, CRM, Document Management, Reporting, and Notifications exist at v1 level.
- Celery + Redis are connected.
- Audit logs exist.
- Approval workflow engine v1 exists.
- RAG v1 works over documents and selected ERP records.
- Search exists through PostgreSQL full-text search or Elasticsearch prototype.
- CI runs tests.
- There is at least basic documentation and ADRs.

If any Phase 2 item is incomplete, do not skip it. Convert the first 1–2 days of Phase 3 into recovery/refactoring days.
